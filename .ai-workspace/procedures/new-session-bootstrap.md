# 新会话低成本启动

## 问题

如果每次新会话都按"把所有相关文档读一遍"来引导，初始注入量会随文档增长而膨胀，
最终既撞上下文窗口，又稀释注意力。更糟的是：**这笔成本每次会话都要付一遍**。

## 最小加载集合

只加载两个文件就可以开始工作：

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `AGENTS.md` | 规范入口：约束、权限分级、委派要件 |
| 2 | `.ai-workspace/tasks/context-checkpoint.md` | 上次做到哪、下一步是什么 |

其余内容**一律按需加载**，不预先读入。

## 按需加载的顺序

```
1. 读检查点                 → 知道当前状态
2. 读 tasks/current.md      → 知道活动任务
3. 查 INDEX.md 并按维度过滤  → 找到相关文档（不是遍历全部）
4. 只读命中的那几篇
5. 需要动代码时，再读对应的 core/ 规则
```

第 3 步是关键：**索引带过滤维度**（按平台、按技术栈、按状态），
所以"找文档"是一次查询，不是一次遍历。

## 纪律

- **不要 resume 长会话**来延续上下文——那样等于每次都付全量成本，而且旧上下文会污染判断。
  正确做法是让上一次会话**落盘**（检查点 + 任务状态），下一次**从文件恢复**。
- 规范入口的体量要盯住：超过预算就拆到 `core/` 里按主题分文件。
  入口是固定成本，**它膨胀的代价是每次会话都要付**。
- 检查点必须短。它一旦变长就退化成小型流水账，失去"快速对齐"的作用。

## 效果

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 初始注入量 | 约 316 KB（≈98k tokens） | 约 14 KB（≈4.4k tokens） |
| 变化 | — | **↓ 约 95%** |

> token 换算为粗略估计，仅用于量级比较。完整口径见
> `.ai-workspace/docs/cost-analysis.md`。
