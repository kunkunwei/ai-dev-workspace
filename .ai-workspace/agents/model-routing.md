# 主代理 / 执行子代理模型路由（primary / deepseek-v4.1-flash）

本文件定义 Kimi Code CLI 的主代理 / 执行子代理分工，以及子代理失败时的编排层处理方式。模型在子代理创建时按别名绑定；工作区不负责启动子代理，也不自建模型池。

## 默认分工

| 任务类型 | 模型别名 | 定位 | 说明 |
|---|---|---|---|
| 主代理：需求理解、方向控制、任务拆分、风险/接口裁决、最终验收 | `primary` | 继承主模型 | 即当前会话主模型；保持完整用户上下文，不拆分 |
| 执行子代理（默认）：文件/日志/Git 扫描、长输出压缩、独立检索 | `custom/deepseek-v4.1-flash` | 默认低成本 | 默认执行子代理，承担边界明确的机械支线 |
| 执行子代理（重推理）：复杂因果分析、疑难调试推演 | `custom/deepseek-v4-pro` | 按需高推理 | 仅当任务确实需要更强推理时显式指定 |
| 执行子代理（长上下文/工具密集）：大仓库扫描、多轮工具调用 | `custom/muse-spark-1.3-contributor` | 按需长上下文 | 上下文很长或工具调用密集的支线 |
| 独立 Expert 子代理 | `custom/deepseek-v4-pro` | 按需高推理 | 仅当额外并行复杂分析确有价值；不得重复主代理判断 |
| Validator | 默认 `custom/deepseek-v4.1-flash`；最终裁决由主代理 | 低 / 继承主模型 | 普通任务不启动例行审查子代理 |

## Kimi Code 运行时模型池

- 当前可用的子代理别名：`custom/deepseek-v4.1-flash`（默认）、`custom/deepseek-v4-pro`、`custom/muse-spark-1.3-contributor`、`primary`。
- 模型池由运行时提供。工作区不再维护 `[secondary_model]` 配置项或相关环境变量开关；能否指定 `model` 参数，以 `Agent` / `AgentSwarm` 工具的实际暴露情况为准。
- **诚实规则**：如果模型池未暴露，或某个别名与池中条目不匹配，不得声称模型已切换；必须如实报告「模型池未生效 / 模型未切换」，并按当前实际使用的模型继续执行。
- 配置变更后需 `/reload` 或新建客户端进程；已创建的子代理不热切换。

## 委派规则

1. 主代理始终负责理解用户需求、确认边界、制定方案、判断风险、编写委派提示和最终验收；不得把模糊需求原样丢给执行子代理解释。
2. 只需 1–2 次简单工具调用时由主代理直接完成，避免子代理启动开销。
3. 预计超过约 3 次搜索/读取、需要读取长文件/长日志、批量扫描多个独立路径，或中间输出会明显污染主上下文时，优先创建或复用执行子代理（默认 `custom/deepseek-v4.1-flash`）。
4. 委派必须包含目标、最小必要事实、`cwd`、允许/禁止路径、权限模式、验证要求和返回格式；执行子代理不裁决接口、不扩大 scope、不做无关重构，只返回结论、关键证据和修改摘要。
5. 多 lane 完全独立、无共享接口和共同因果链时，可并行创建执行子代理；已有同类子代理时优先复用。
6. 复杂耦合、protected 接口、高风险迁移/部署/数据操作、跨仓库架构和证据冲突，由主代理直接建立因果链并作出决策。
7. 只有独立并行专家分析确有价值或用户明确要求时，才额外创建高推理子代理（`custom/deepseek-v4-pro`）；不得让子代理执行例行搜索、机械 Git 检查、普通 diff 转述或常规最终审查。
8. 子代理模型在创建时绑定；运行中不热切换。任何模型均继承工作区安全规则，模型切换不扩大文件、Git、SSH、Docker、ROS 或 Jetson 权限。
9. Jetson 未开机或用户未声明已上线时，不进行 SSH 连通性重试；上线后默认仅执行 `READ_ONLY` 白名单检查。

## 子代理失败接管（未实现 / KNOWN GAP）

1. **当前状态：未实现。** 运行时不会在子代理失败后自动切换模型并重建子代理。子代理失败时，主代理只报告失败类别和已产生的影响，不得声称发生了任何自动降级或接管。
2. 以下设计意图保留，供将来实现时遵循：子代理因运行时可用性故障（无法启动、无有效响应或超时）失败时，主代理可创建或复用执行子代理按原 scope 继续，并原样传递原委派的 `prompt`、`cwd`、允许/禁止路径、测试策略和安全边界。
3. 同一委派最多接管一次，不递归接管；接管前必须确认原委派已停止，不得并发写入同一文件。
4. 用户或权限策略拒绝、scope/cwd 校验失败、参数错误、危险操作确认、protected 边界，以及普通实现/测试失败，均不属于可用性故障，禁止借接管绕过；权限语义（只读保持只读）在任何情况下都不因接管而放宽。
5. 实现后报告必须写明替代模型别名、原始失败类别、执行子代理的修改和主代理的独立验证结果。

## 推荐链路

主代理理解需求并确定边界 → 边界明确的大量扫描交给执行子代理（`custom/deepseek-v4.1-flash`）→ 实际代码按 lane 交由执行子代理单次实施 → 子代理失败时如实报告失败，不做自动接管 → 主代理检查任务范围 diff → 进入用户手动现象/抓包驱动的联调。

## 联调优先规则

- 各 lane 完成后不启动独立 Validator 做全量重复检查。
- 主代理只确认 diff 未越过本次任务范围，然后直接进入联调。
- 优先依据用户手动测试现象、HTTP/WebSocket 抓包和关键 ROS/服务日志定位所属 lane。
- 稳定且未修改的模块不重新分析；修复只返回故障所属 lane，一次修改后再次等待用户观察。
