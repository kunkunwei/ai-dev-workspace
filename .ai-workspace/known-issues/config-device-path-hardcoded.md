# 别名规则硬编码设备路径，换 USB 端口后静默失效

## 现象

设备上表现为**部分功能缺失**而不是整体故障：

- 某个数据项一直没有值（采集端看不到）
- 另一个模块完全无响应（指示灯不亮、状态页空）

两者都**不报错、不崩溃**，只是"没有数据"。

## 根因

别名规则里写的是**硬编码的物理路径**，例如：

```
SUBSYSTEM=="tty", KERNELS=="1-2.4.4.4", SYMLINK+="ttyDeviceA"
```

而设备实际接在了 `1-2.1.1` / `1-2.1.3`。硬件拓扑变了（换 USB 口、换线、换分支），
规则不再匹配，别名文件根本不会被创建。

**为什么静默**：依赖方按固定别名路径打开设备，路径不存在时只是打开失败；
如果失败处理是"重试"而不是"上报"，就会表现为"永远没有数据"。

## 处置

1. **先用实际值，不要猜**：

   ```bash
   udevadm info -q path -n /dev/ttyUSB0
   ```

   取真实物理路径，再写规则。

2. 规则一律按 `KERNELS==` 物理端口匹配，**不要按 `ttyUSB*` 编号匹配**——
   编号在每次开机、每次插拔后都可能变。

3. 改完重载：

   ```bash
   udevadm control --reload-rules
   udevadm trigger --subsystem-match=tty
   ```

   改之前备份原规则文件（带时间戳），便于回滚。

## 判据（30 秒分层）

| 观察 | 判断 |
|---|---|
| 别名文件不存在 | 规则层：路径不匹配 |
| 别名存在，但无进程持有，且内核日志有超时错误 | 驱动/芯片层：设备挂死 |
| 别名存在且被占用 | 应用层：看解析日志与数据上报 |

**分层的好处**：三个层次的现象几乎一样（都是"没数据"），但处置方式完全不同。
先分清在哪一层，再动手。

## 教训

- 硬编码物理拓扑的配置，在设备会换端口/换线时必然失效
- 优先用自动探测生成规则，或至少把拓扑值抽成一个可改的配置项
- "部分数据缺失"这类现象要优先怀疑**设备层**，而不是应用逻辑
