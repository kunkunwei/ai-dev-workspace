# 03 · 踩坑记录：4 条真实工程坑

> 这些坑都是真实踩过的，纯技术、可复用，与具体行业无关。
> 场景：用「单页面板 + GitHub 私有仓」做投递进度看板，AI 侧读写私有仓的 `data.json`。

---

## 坑 1：`file://` 打开的单页应用，localStorage 会丢

**现象**：「数据和应用同步配置一起消失」。双击 HTML 用本地文件协议打开时，
浏览器对 `file://` origin 的 `localStorage` 不保证持久，换个路径、清一次临时数据、
或浏览器升级都可能清空。于是**数据和「连到私有仓的同步配置」一起没了**。

**正解**：部署到 `https://`（如 GitHub Pages）用**稳定 origin**。
`https://<用户名>.github.io/<仓名>/` 的 origin 是稳定的，`localStorage` 按 origin 隔离且持久。
以后只用这个在线地址，别再用双击 `file://` 打开。

> 关联坑 4：本地文件协议还会让「多端同步」无从谈起——每台机器的 localStorage 是各管各的，
> 一换设备数据就「丢」了。

---

## 坑 2：往 GitHub Contents API 预置文件时，文件内容是原始 JSON，不是 base64

**现象**：面板从私有仓拉 `data.json`，应用侧代码 `JSON.parse(atob(content))` 直接抛错，
被 `try/catch` **静默吞掉**。表现是「同步配置正常，但数据不出现」——没有报错，极难排查。

**根因**：GitHub Contents API 的「获取内容」返回的是 base64，但**「写入内容」接口收的是
原始内容字节**，GitHub 自己会套 base64 存进去。如果预置时把内容先 base64 再写入，
就存了双重 base64。面板拉回来后 `atob(content)` 解出的不是 JSON，于是 `JSON.parse` 抛错。

**判别法**：写完后**从远端 clone 回来复核一次**，能解码成可读 JSON 才算对。

**正解**：

- 用 GitHub Contents API 写入 → 传**原始 JSON 字符串**（`"content": <原始 JSON>`）
- 用 `git push` 直接写文件 → 写的也必须是**原始 JSON**
- 两种方式殊途同归：文件里存的是原始 JSON，不是 base64

---

## 坑 3：同步的 `savedAt`「远端更新才采用」规则

**背景**：单页面板的云同步逻辑是**「远端 `savedAt` 比本地新就采用」**（单行判断，无冲突合并）。

**现象**：AI 替用户新增记录，写回私有仓后用户刷新面板，**新记录不出现**。

**根因**：写回的 `data.json` 里 `savedAt` 没设，或设成了比面板本地值更旧的值。
面板本地已有一次保存记录（本地 `savedAt` 较新），于是按规则**忽略了远端**。

**正解**：从外部写回数据时，**必须把 `savedAt` 设成大于对端当前值**（例如取当前毫秒时间戳）。
这样面板一刷新就会采用远端。

**更稳的姿势**：预置云端数据时也利用这条规则——把 `savedAt` 设成一个**远大于空白本地状态**的值，
面板首次配置好同步、一刷新就会自动把数据拉下来，**连「导入」按钮都不用点**。

---

## 坑 4：last-write-wins 竞争

**现象**：AI 从外部改数据（写回私有仓），应用正开着并保存，会把 AI 的改动**覆盖掉**。

**根因**：这套方案没有冲突合并，是 **last-write-wins**。谁最后保存谁赢。
应用开着时它本地有一份较新的内存态，AI 从远端读到的是旧数据，AI 写回后，应用紧接着保存，
就用应用本地（旧 + 用户最新操作）覆盖了 AI 的远端改动。

**正解（流程纪律，而非代码）**：

1. **从外部改数据前，必须先拉取最新版**——从私有仓 `git pull` 或 API 取当前 `data.json`，基于最新版改
2. **改的时候提醒应用端暂停保存**（或明确告知「正在外部修改，先别动面板」）
3. 写回后让用户**刷新面板**再继续操作，避免面板用内存态反写

**本质**：last-write-wins 不是 bug，是取舍。要省掉「拉取-改-提醒」这套流程，
就得引入真正的冲突合并或 CRDT——对个人投递台账这种低频低并发场景，不值得，
流程纪律就够了。

---

## 附：一句话总结

> `file://` 会丢数据 → 用 `https://` 稳定 origin；
> 预置文件传原始 JSON（GitHub 自己套 base64）；
> 外部写回时 `savedAt` 要比对端新；
> last-write-wins 下，外部改数据前先拉最新版、提醒应用暂停保存。
