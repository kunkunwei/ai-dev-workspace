# 04 · 工具选型调研与许可注意事项

> 调研面向「应届生秋招 + 公司官网渠道」场景。结论按「能不能用在这个场景」排序，不按星数。
> 日期：2026-09-25。

---

## 一、一句话结论

| 需求 | 有没有现成的 | 用哪个 |
|---|---|---|
| **一键补全在线简历** | ✅ 有，且很合场景 | `1lck/AI-Resume-Form-Filling-Assistant` |

## 二、在线简历一键补全 —— 首推

### ⭐ `1lck/AI-Resume-Form-Filling-Assistant`　★185　JavaScript　GPL-3.0

Chrome / Edge 侧边栏扩展，**无构建步骤，源码目录直接加载**。

**为什么适合**：

- **直接粘贴简历原文**（或上传带文字层的 PDF）→ 大模型**只做「字段映射」**（判断页面字段对应简历里的哪个路径）→ 真正写值由本地内容脚本确定性执行。不是让 AI 乱填页面，行为可控、失败可查
- **三种填充模式**：整页填充 / 增量填入（跳过已有值）/ 选区填入（框选一块只填那块）
- 支持 `input`、`textarea`、`select`、单选组、多选组、`contenteditable`、部分只读日期控件与日期面板；填充前会展开「展开 / 查看更多」折叠块再扫描
- **schema 专门按中文校招强化**：教育经历、实习经历、校园经历、学历类型 / 培养方式 / 实验室 / 导师 / 学号
- **默认只填值、不自动提交**——填完检查再点提交
- 支持维护**多份简历模板**（按方向切换），可一键导出 / 导入 JSON 备份

**限制（README 自己写的）**：不处理 `input[type=file]` 附件上传；不内置 OCR（扫描版 PDF 要先 OCR）；跨域 iframe 内的字段可能识别不到；极端自定义控件仍需单站点适配。

⚠️ **隐私**：API key 与简历存在本地 `chrome.storage.local`；但**做字段映射时会把简历文本发给模型接口**（含手机号、邮箱、生日）。不想外传就别配在线模型。

## 三、投递进度管理

### ⭐ 轻量替代：`Echo6v9o/job-tracker`　★2　MIT

**单个 HTML 双击就用，零依赖，可选同步到 GitHub 私有仓。**

- 投递看板：按公司 / 岗位 / 阶段跟进，支持拖拽改状态、进度时间线、临近提醒
- 数据模型：`records` / `companyFlags` / `view` / `savedAt`
- 云同步：数据放私有仓 `data.json`，每次保存自动 commit，多端同步，误删可从仓库历史恢复
- **license 宽松（MIT）**，可自由引用 / 托管

> 用它做看板而不是部署独立服务型应用，理由见 [`01-闭环设计.md`](01-闭环设计.md)：避免引入第二套事实源。

## 四、一键投简历 —— **不建议用**

现成项目真实存在且活跃，但对官网渠道不适用：

| 项目 | ★ | 覆盖 |
|---|---|---|
| `loks666/get_jobs` | 8.5k | Java + Playwright，覆盖多家招聘平台，社区最活跃 |
| `geekgeekrun/geekgeekrun` | 2.6k | 招聘平台自动批量开聊 |
| `Ocyss/boss-helper` | 2.3k | 招聘平台助手扩展 |
| `yangfeng20/boss_batch_push` | 850 | 招聘平台批量投递脚本（作者已声明未适配新版页面） |
| `yangfeng20/ai-job` | 685 | AI 坐席 24h 自动投递 + 自动回 HR |
| `StartripAI/findjobs` | 4 | 唯一提供「公司官网表单自动填」的项目（海外 ATS 适配器） |

**不用的三个理由**：

1. **全都是「招聘平台内投递」**，而投的是**公司官网**。唯一碰官网的 `StartripAI/findjobs` 只有 4 星，且适配器是**海外 ATS**，中文官网用不上。
2. **封号风险**：违反平台用户协议，被识别即封号。求职季账号被封的损失远大于省下的填表时间。
3. 权威项目作者自己在 README 里写「其它平台未测试 / 不建议用」。

**技术上的根本原因**：几十家公司的官网表单字段各不相同，「通用自动填表」只可能在**填值**这一层做成（靠 AI 做字段映射），不可能在**提交**这一层做成。这就是为什么需求 (c) 有解、(b) 无解。

## 五、JD 匹配 / 简历定制（"AI 求职助手"类）

这类全是 **AI skill / agent 形态**，不是独立软件，需要配 AI coding CLI 环境：

| 项目 | ★ | 干什么 |
|---|---|---|
| `Paramchoudhary/ResumeSkills` | 2.5k | AI agent skills 集合，简历优化 + 求职申请 |
| `DanielPan12/JobHuntBot` | 838 | Agent 驱动的申请工作流 + 本地进度仪表盘 |
| `career-ops-hq/career-ops` | 73k | 跑在 AI coding CLI 里，扫招聘门户、把岗位评成结构化报告、定制 CV、跟踪投递。但瞄准**海外 ATS**（LinkedIn / Indeed / Workday / Greenhouse），中文链路不适用 |
| `wanyichen06/LLMInternSkill` | 322 | 面向在校生：简历润色、JD 定制、证据把关、面试拷问 |
| `sharzoy/auto-job-apply` | 157 | 简历解析 → JD 硬性条件核对 → A/B/C 评分 → 生成投递包（保留人工确认） |

> 星多不等于适用——`career-ops-hq/career-ops` 是海外向的。

**判断**：这些能力自己的工作台 AI 直接就能做，而且**比它们准**——因为有证据索引那张「能说什么 / 不能说什么」的表（见 [`02-防幻觉评估机制.md`](02-防幻觉评估机制.md)），通用 skill 没有。

## 六、Gitee

基本没有原创项目（匿名 API 限流导致搜索返回空），只找到热门项目的镜像（`gitee.com/yangfeng20/ai-job` 等）。这类工具主要托管在 GitHub。

## 七、最终建议

1. **装 `1lck/AI-Resume-Form-Filling-Assistant`** 解决官网填表——唯一「用了就省事、不引入新事实源」的项目
2. **进度面板**用轻量单 HTML 方案（如 `Echo6v9o/job-tracker`），数据放私有仓；不部署独立服务型应用（理由见 [`01-闭环设计.md`](01-闭环设计.md)：会变成第二套事实源）
3. **投递动作自己点**，别上自动投递脚本
4. JD 匹配、简历定制交给工作台的 AI——有证据索引，通用工具比不过

## 八、许可注意事项（重要）

| 项目 | 许可 | 含义 / 约束 |
|---|---|---|
| `Echo6v9o/job-tracker` | **MIT** | 可引用 / 托管，**必须保留 LICENSE 与署名**。本 case study **不 vendor 它的代码**，只在文档里给链接 |
| `1lck/AI-Resume-Form-Filling-Assistant` | **GPL-3.0** | ⚠️ **绝不能把它的代码复制进本仓**（会传染 GPL，整个仓库都得变 GPL）。只能给链接，让使用者自行安装 |
| `tools/to_formfill.py`（本 case study 自带） | **MIT** | 独立实现（读 YAML → 输出符合填表扩展所需格式的 JSON），**不包含对方代码**，因此本项目用 MIT |

**实践建议**：
- 引用第三方代码前先确认许可，`GPL/AGPL` 类一律只链接、不 vendoring
- `PolyForm Noncommercial` 类（如 `zoepan0109-coder/...`）个人自用无碍，但不能进商业分发
- 托管第三方页面代码（如把 `index.html` 放到 GitHub Pages）时，保留原项目的 LICENSE 与署名
